## 2. Почему тема актуальна — аргументация (с проверенными источниками)

- Систематический обзор 121 статьи с конференции NeurIPS 2017 (из 679 изученных
  рефератов) показал: **лишь около 3% работ по машинному обучению вообще проводят
  формальную статистическую проверку** сравнения модели с baseline — подавляющее
  большинство просто сравнивает числа «на глаз». Источник:
  Király, F. J., Mateen, B., & Sonabend, R. (2018). *«NIPS — Not Even Wrong? A
  Systematic Review of Empirically Complete Demonstrations of Algorithmic
  Effectiveness in the Machine Learning and Artificial Intelligence Literature»*.
  [arXiv:1812.07519](https://arxiv.org/abs/1812.07519).
- Это признанная системная проблема области, не частное мнение: Lipton, Z. C., &
  Steinhardt, J. (2018). *«Troubling Trends in Machine Learning Scholarship»*, доклад
  на ICML 2018. [arXiv:1807.03341](https://arxiv.org/pdf/1807.03341).
- Более широкий контекст «кризиса воспроизводимости» в ML: свыше 70% исследователей не
  могут воспроизвести чужие эксперименты, утечка данных (data leakage) найдена в 294
  статьях из 17 разных научных областей.
- **Почему тема не «заезжена» как учебный проект**: в отличие от тем вроде A/B-теста на
  Cookie Cats или честности гача-дропа (хобби-контент с «эффектной» историей для
  блогеров/Kaggle), эта тема — про метод, а не про домен, поэтому её почти никто не
  берёт для pet-проекта/портфолио, хотя академически она куда серьёзнее обоснована
  (Demšar 2006 — тысячи цитирований).
- **Живая иллюстрация проблемы — пример работы, который дали к курсу** («Анализ цен на
  мебель», датасет с Kaggle, 26-слайдовая презентация команды из 3 человек): там прямо
  сравнивают линейную регрессию (R²=0.587) и нейросеть (R²=0.6216) и заявляют «нейросеть
  лучше» — **без единой проверки, значима ли разница в 0.035 R² или это шум**. Это
  буквально иллюстрация той самой ошибки, которую разбирает ваша тема — хороший
  риторический крючок для защиты.

### В чём именно новизна (важно — разбиралось отдельно и подробно)

Классические методы корректной проверки (Dietterich 1998, Nadeau & Bengio 2000,
Demšar 2006) тестировались на алгоритмах своего времени:
- **Dietterich (1998)** использовал C4.5 (дерево решений 1993 года) против обычной
  нейросети с backprop, причём доказывал проблему на **специально сконструированных
  синтетических данных** (`epsilon`, `EXP6`), где заранее известно, что разницы между
  моделями нет — это контролируемый эксперимент, не анализ реальных данных.
- **Demšar (2006)** использовал C4.5, наивный Байес и kNN на 14 классических датасетах
  UCI (iris, wine, mushroom и т.п.).
- Random Forest (Брейман) опубликован в 2001 году — то есть ко времени Dietterich (1998)
  его не существовало, а ко времени Demšar (2006) он уже существовал 5 лет, но ещё не
  был тем самым стандартным выбором «по умолчанию» (мейнстримом стал ближе к середине
  2010-х) — и сам Demšar всё равно не включил его в свои эксперименты.
  **Важно не переупрощать этот пункт** — утверждение «Random Forest не существовал»
  некорректно для Demšar (2006), корректная формулировка: «ещё не был стандартом».
- `HistGradientBoostingClassifier` из scikit-learn появился только в **2019 году**
  (версия 0.21) — это единственный пункт, который постфактум верен без всяких оговорок
  для обеих классических работ.

**Вывод по новизне:** это не изобретение новой статистики (никто не ждёт этого от
3-недельного соло-проекта), а **честная проверка переносимости** известного результата
на современный набор моделей и открытые датасеты, для которых эти конкретные цифры
(степень расхождения наивного и корректного теста) никогда никем не считались — потому
что инструментов, которыми вы будете пользоваться, тогда просто не было.

## 7. Экспериментальный дизайн — пошагово, с кодом

### Шаг 1 — Baseline accuracy

```python
from sklearn.model_selection import cross_val_score
import numpy as np

results = {}
for ds_name, (X, y) in datasets.items():
    results[ds_name] = {}
    for model_name, model in models.items():
        scores = cross_val_score(model, X, y, cv=10, scoring='accuracy')
        results[ds_name][model_name] = scores
```

### Шаг 2 — ГЛАВНЫЙ демонстрационный результат: наивный vs корректные тесты

На `digits`, пара Random Forest vs Logistic Regression:

```python
from scipy import stats
from mlxtend.evaluate import paired_ttest_kfold_cv, paired_ttest_5x2cv, mcnemar, mcnemar_table

# (а) НАИВНЫЙ тест — методологически некорректен, делаем специально для демонстрации разницы
t_naive, p_naive = stats.ttest_rel(results['digits']['rf'], results['digits']['logreg'])

# (б) corrected resampled t-test (Nadeau & Bengio)
t_corr, p_corr = paired_ttest_kfold_cv(estimator1=rf, estimator2=logreg, X=X, y=y, cv=10)

# (в) 5x2cv paired t-test (Dietterich)
t_5x2, p_5x2 = paired_ttest_5x2cv(estimator1=rf, estimator2=logreg, X=X, y=y)

# (г) McNemar на одном train/test сплите (отдельная демонстрация, другой дизайн)
tb = mcnemar_table(y_target=y_test, y_model1=pred_rf, y_model2=pred_logreg)
```

**Ожидаемый и методологически предсказанный результат:** `p_naive` систематически меньше,
чем `p_corr`/`p_5x2` — наивный тест чаще «находит» значимость там, где корректные методы

### Шаг 3 — Friedman + Nemenyi по всем датасетам

```python
import pandas as pd
from scipy.stats import friedmanchisquare
import scikit_posthocs as sp

score_matrix = pd.DataFrame({
    model_name: [np.mean(results[ds][model_name]) for ds in datasets]
    for model_name in models
}, index=list(datasets.keys()))

stat, p_friedman = friedmanchisquare(*[score_matrix[m] for m in score_matrix.columns])
if p_friedman < 0.05:
    nemenyi_results = sp.posthoc_nemenyi_friedman(score_matrix.values)
```

## 8. Как не наступить на грабли

- Наивный `ttest_rel` на фолдах CV — только как демонстрация ошибки, никогда как
  финальный результат.
- McNemar — только для одного train/test разбиения, не для фолдов CV.
- Friedman/Nemenyi нужен от 5+ датасетов — у нас ровно 5, честно признать как границу.
- Множественные попарные сравнения — обязательно поправка Holm/Bonferroni.
- Не тюнить гиперпараметры глубоко на тех же данных — риск data leakage, использовать
  дефолты sklearn, указать как ограничение.
- Обсуждать не только p-value, но и величину эффекта (доверительный интервал на разницу
  accuracy).

## 10. Вероятные вопросы на защите — готовые ответы

- *«В чём тут статистика, а не ML-эксперимент?»* → центр работы — сравнение методов
  проверки гипотез, модели — просто источник данных для теста; показать таблицу
  «4 теста → 4 разных p-value на одном и том же вопросе».
- *«Почему не SOTA-модели?»* → выбор моделей не предмет работы, нужно было разнообразие
  семейств (линейная/бэггинг/бустинг), а не state-of-the-art.
- *«Почему 5 датасетов, а не 20-30 как у Demšar?»* → честно: ограничение по времени
  (3 недели, соло), явно обозначено как ограничение; направление эффекта устойчиво
  воспроизводится и на таком объёме.
- *«Разве 0.91 vs 0.89 не очевидно значимо?»* → именно эта ложная интуиция и
  развенчивается работой.
- *«Почему 97% исследователей не используют эти тесты?»* → NeurIPS с 2021 ввёл чеклист
  про error bars, но это самоотчёт с низкой планкой требований — не гарантирует именно
  корректный тест для CV-ситуации.
